🛡️ 1. Blue Team Core Philosophy — สถาปัตยกรรมตั้งรับและปรัชญาป้องกัน
หาก Red Team (ทีมโจมตี) เปรียบเสมือน "กระจกเงาสะท้อนจุดอ่อน" ของระบบ Blue Team (ทีมตั้งรับ) คือ "วิศวกรผู้สร้างกำแพง ป้อมปราการ และเรดาร์ตรวจจับ" ภารกิจของ Blue Team คือการปกป้องสินทรัพย์ข้อมูล (CIA Triad), ลดพื้นที่การโจมตี (Attack Surface Reduction), และตรวจจับภัยคุกคามให้ได้ก่อนที่จะเกิดความเสียหาย
🏛️ 1.1 เสาหลักความมั่นคงปลอดภัย (Security Pillars)
CIA Triad & Defense-in-Depth
1. Confidentiality (การรักษาความลับ)

ป้องกันไม่ให้ผู้ไม่มีสิทธิ์เข้าถึงข้อมูลสำคัญ เช่น รหัสผ่าน, ข้อมูลบัตรเครดิต, หรือไฟล์เอกสารส่วนบุคคล (ป้องกัน IDOR / Data Leaks)

2. Integrity (ความถูกต้องสมบูรณ์)

ป้องกันไม่ให้ข้อมูลถูกดัดแปลงแก้ไขโดยไม่ได้รับอนุญาต เช่น แก้ราคาสินค้าเป็น 0 บาท หรือถูกฉีดคำสั่ง SQL/Webshell

3. Availability (ความพร้อมใช้งาน)

ระบบและบริการต้องพร้อมให้บริการเสมอ ไม่ล่มจากการโดน DDoS Attack หรือการใช้ Resource จนเซิร์ฟเวอร์ค้าง (ReDoS / Sleep SQLi)

แนวคิด Zero Trust Architecture (Never Trust, Always Verify):
  • ไม่มีใครปลอดภัยโดยสมบูรณ์: แม้คำขอจะมาจาก IP ภายในเครือข่ายออฟฟิศ หรือเป็น User ที่ล็อกอินแล้ว ทุก Request ต้องถูกตรวจสอบสิทธิ์ (Verify Explicitly) ซ้ำเสมอ
  • Least Privilege Access: มอบสิทธิ์ให้น้อยที่สุดเท่าที่จำเป็นในการทำงาน เช่น เว็บเซิร์ฟเวอร์ (www-data) ไม่ควรมีสิทธิ์อ่านไฟล์ /etc/shadow หรือเขียนโฟลเดอร์หน้าเว็บหลัก
  • Assume Breach: ปฏิบัติงานบนสมมติฐานว่า "ระบบอาจมีผู้ไม่หวังดีเล็ดลอดเข้ามาอยู่แล้ว" จึงต้องมี Log และ Audit Trail คอยสอดส่องทุกความเคลื่อนไหวตลอด 24/7

📊 2. Log Analysis & SOC Monitoring — ศิลปะการแกะรอยผู้บุกรุก
ในศูนย์ปฏิบัติการเฝ้าระวังความมั่นคงปลอดภัย (Security Operations Center - SOC) "Log คือพยานหลักฐานที่ไม่เคยโกหก" ทุกครั้งที่แฮกเกอร์ส่ง Request เข้ามา ไม่ว่าการโจมตีจะสำเร็จหรือล้มเหลว ร่องรอยจะถูกบันทึกไว้ใน Web Server Access Log เสมอ

🧱 3. Web Application Firewall (WAF) — กำแพงดักจับการโจมตี Layer 7
WAF (Web Application Firewall) ทำงานคั่นกลางระหว่างโลกภายนอกกับเว็บเซิร์ฟเวอร์ โดยคอย ตรวจสอบเนื้อหาใน HTTP Request (Header, Cookie, Query String, และ POST Body) เพื่อมองหาลายเซ็นการโจมตี (Signatures) และสกัดกั้นด้วยรหัส 403 Forbidden ก่อนที่คำขออันตรายจะหลุดเข้าไปถึงตัวแอปพลิเคชัน
🛡️ 3.1 ModSecurity & OWASP Core Rule Set (CRS)
Layer 7 Deep Packet Inspection
ตัวอย่างกฎ WAF (SecRule) ในภาษา ModSecurity ที่ใช้ตรวจจับการโจมตี:
# ดักจับคำสั่ง SQL Injection ที่มีคำว่า UNION และ SELECT: SecRule ARGS "@rx (?i:union.*select)" \ "id:1001,phase:2,deny,status:403,msg:'SQL Injection Attack Detected!'" # ดักจับ Directory Traversal (../ หรือ ..\): SecRule REQUEST_URI "@rx (?:\.\./|\.\.\\)" \ "id:1002,phase:2,deny,status:403,msg:'Path Traversal Attempt Blocked!'"

📜 5. HTTP Security Headers — 5 ปราการคำสั่งพิทักษ์เบราว์เซอร์
HTTP Security Headers คือคำสั่งพิเศษที่เว็บเซิร์ฟเวอร์ส่งแนบไปใน Response Header เพื่อ สั่งการให้เว็บเบราว์เซอร์ของผู้ใช้เปิดเกราะป้องกันความปลอดภัย ในระดับเครื่องลูกข่าย บล็อกการโจมตีอย่าง XSS, Clickjacking และการถูกดักฟังเครือข่าย
🛡️ 5.1 สรุป 5 Security Headers ที่ทุกเว็บต้องมี
OWASP Secure Headers Project
1. Content-Security-Policy (CSP)

กำหนด Whitelist โดเมนที่อนุญาตให้โหลดสคริปต์ และ บล็อก Inline Script (<script>) ทันที เป็นอาวุธสังหาร XSS ที่ทรงพลังที่สุด!

2. Strict-Transport-Security (HSTS)

บังคับให้เบราว์เซอร์เชื่อมต่อผ่าน HTTPS เท่านั้น ตลอด 1-2 ปี ป้องกันการโดนแอบตัดเป็น HTTP ธรรมดา (SSL Stripping)

3. X-Frame-Options: DENY

ห้ามไม่ให้เว็บไซต์อื่นนำเว็บเราไปฝังใน <iframe> ป้องกันการโจมตีหลอกคลิก Clickjacking

4. X-Content-Type-Options: nosniff

สั่งให้เบราว์เซอร์เชื่อค่า Content-Type ห้ามพยายามเดาชนิดไฟล์เอง ป้องกันการรันโค้ดผ่าน MIME Confusion

5. Referrer-Policy: strict-origin

ป้องกันไม่ให้ URL ลับหรือ Token ที่อยู่บน Address Bar รั่วไหลออกไปภายนอกเมื่อผู้ใช้คลิกลิงก์

🚨 7. Incident Response (PICERL Framework) — รับมือเมื่อเกิดเหตุฉุกเฉิน
ไม่มีระบบใดในโลกที่ปลอดภัย 100% เมื่อเกิดเหตุการณ์บุกรุกจริง (Security Incident) สิ่งสำคัญที่สุดคือ กระบวนการตอบสนองที่เป็นระบบตามมาตรฐานสากล (NIST SP 800-61 / SANS PICERL) เพื่อหยุดยั้งความเสียหาย และฟื้นฟูระบบให้กลับมาทำงานได้อย่างรวดเร็วและปลอดภัย
📋 7.1 วงจร 6 ขั้นตอนของ Incident Response (SANS PICERL)
NIST SP 800-61 / SANS Standard
1. Preparation (การเตรียมความพร้อม)

สำรองข้อมูล (Clean Backup), ซักซ้อมแผนรับมือ, จัดเตรียมเครื่องมือ Forensics

2. Identification (การระบุและตรวจจับ)

ตรวจจับร่องรอยการบุกรุก, วิเคราะห์ Log, ยืนยันว่าเกิด Incident จริงหรือไม่

3. Containment (การควบคุมพื้นที่ความเสียหาย)

ตัดการเชื่อมต่อเครื่องที่ติดเชื้อออกจากเครือข่าย ป้องกันการแพร่กระจาย (Lateral Movement)

4. Eradication (การกำจัดและถอนรากถอนโคน)

ลบ Webshell, สแกนมัลแวร์, อุดช่องโหว่ที่แฮกเกอร์ใช้เจาะเข้ามา

5. Recovery (การกู้คืนและนำระบบกลับมา)

กู้ระบบจาก Clean Backup, บังคับเปลี่ยนรหัสผ่านทุกบัญชี, มอนิเตอร์อย่างใกล้ชิด

6. Lessons Learned (การถอดบทเรียน)

เขียนรายงาน Post-Incident Review สรุปต้นตอ และปรับปรุงนโยบายป้องกันในอนาคต
