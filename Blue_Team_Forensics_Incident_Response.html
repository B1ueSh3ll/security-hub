💾 1. Memory Forensics & Volatility 3 — การชันสูตรแรมของเครื่องที่ถูกแฮก
มัลแวร์ยุคใหม่ (Fileless Malware) และโทรจันขโมยรหัสผ่าน มักทำงานอยู่ใน RAM (หน่วยความจำชั่วคราว) โดยไม่บันทึกลงฮาร์ดดิสก์!
กฎเหล็กอันดับ 1 ของ Forensics: "ห้ามสั่ง Restart เครื่องเด็ดขาด!" เพราะข้อมูลใน RAM ทั้งรหัสผ่าน, คำสั่งที่แฮกเกอร์พิมพ์, และ IP เชื่อมต่อจะหายไปทันที
เครื่องมือมาตรฐานสากลคือ Volatility 3 (vol.py)

Plugin Reference
  • windows.pslist / windows.psscan: แสดงรายชื่อ Process และค้นหา Process ที่แอบซ่อน (Hidden by Rootkit)
  • windows.netscan: สแกนหา Socket TCP/UDP ดูว่าเครื่องกำลังเชื่อมต่อไปยัง C2 Server (IP / Port) ใด
  • windows.hashdump: ดึง NTLM Password Hash ของทุก User บนเครื่องออกมาจาก RAM
  • windows.malfind: ตรวจหา Injection Code ในหน่วยความจำ (หน้าความจำที่มีสิทธิ์ PAGE_EXECUTE_READWRITE)
🦠 2. Static Malware Analysis — การวิเคราะห์มัลแวร์เบื้องต้นโดยไม่ต้องรันไฟล์
เมื่อพบไฟล์ต้องสงสัย ห้ามดับเบิ้ลคลิกรันเด็ดขาด!
การวิเคราะห์เบื้องต้นเรียกว่า Static Analysis คือการตรวจสอบคุณลักษณะภายนอก: ค่า Hash (SHA-256), สตริงคำสั่งลับ (strings), และรายการฟังก์ชันที่นำเข้า (Imported APIs)
🔬 4 สเต็ป Static Analysis ก่อนส่งต่อแล็บวิจัย
Triage Workflow
1. คำนวณค่า Hash & VirusTotal
รันคำสั่ง sha256sum evil.exe แล้วนำค่า Hash ไปค้นหาบน virustotal.com หากเคยตรวจพบจะทราบชื่อมัลแวร์ทันที
2. ดึงสตริงด้วยคำสั่ง strings
รัน strings -n 8 evil.exe เพื่อส่องหา URL, IP แฮกเกอร์, ข้อความขู่กรรโชก (Ransomware note), หรือคีย์รีจิสทรี
3. ตรวจสอบ Packer / Entropy
ใช้โปรแกรม Detect It Easy (DiE) เพื่อดูว่ามัลแวร์ถูกเข้ารหัสหรือบีบอัดด้วย UPX มาหรือไม่ เพื่อถอดออกก่อนวิเคราะห์
4. ส่อง Imported Windows APIs
หากพบฟังก์ชันอย่าง CreateRemoteThread, WriteProcessMemory แสดงว่ามีพฤติกรรม Process Injection แน่นอน
🚨 3. NIST SP 800-61 Rev. 2 — กรอบการรับมือภัยคุกคาม 6 ขั้นตอน (PICERL Framework)
