⚡ 3. The Power of XOR & One-Time Pad (OTP) — รากฐานของระบบ Crypto ยุคใหม่
การดำเนินการทางตรรกศาสตร์ที่สำคัญที่สุดในโลกของการเข้ารหัสลับคือ Bitwise XOR (Exclusive OR หรือเครื่องหมาย ⊕ / ^)
XOR มีคุณสมบัติวิเศษที่เป็นรากฐานของทั้ง Stream Ciphers, One-Time Pad, และ Block Cipher Modes
🔬 Bitwise XOR Visual Lab: สังเกตคุณสมบัติ Self-Inverting
กฎมหัศจรรย์ของ XOR:
1) A ⊕ 0 = A
2) A ⊕ A = 0
3) (A ⊕ B) ⊕ B = A   <-- ใช้ Key เดียวกัน XOR ซ้ำ ได้ค่าเดิมคืนทันที! (Symmetric)
💣 ช่องโหว่ยอดฮิตใน CTF: One-Time Pad Key Reuse (การใช้ Key ซ้ำ)
CWE-321 / Many-Time Pad
One-Time Pad (OTP) ได้รับการพิสูจน์ทางคณิตศาสตร์โดย Claude Shannon ว่ามีความปลอดภัยระดับสมบูรณ์แบบ (Perfect Secrecy) แต่มีเงื่อนไขเหล็ก 3 ข้อ: 1. Key ต้องสุ่มแท้ (True Random), 2. Key ต้องยาวเท่าข้อความ, 3. ห้ามใช้ Key ซ้ำเด็ดขาด!
🚩 จะเกิดอะไรขึ้นถ้าแฮกเกอร์เจอการใช้ Key ซ้ำ (C1 ⊕ C2)?
สมมติผู้ส่งส่ง 2 ข้อความด้วย Key เดียวกัน:
C1 = P1 ⊕ Key   และ   C2 = P2 ⊕ Key
เมื่อแฮกเกอร์นำ Ciphertext ทั้งสองมา XOR กัน:
C1 ⊕ C2 = (P1 ⊕ Key) ⊕ (P2 ⊕ Key) = P1 ⊕ P2
ผลลัพธ์คือ Key หายไปอย่างสิ้นเชิง! เหลือเพียง Plaintext สองข้อความ XOR กัน แฮกเกอร์สามารถใช้เทคนิค Crib Dragging หรือช่องว่าง (Space 0x20) เพื่อกู้ข้อความทั้งสองกลับมาได้ 100%!
🧱 4. Modern Symmetric Ciphers — AES & The Trap of Modes (ECB vs CBC vs GCM)
AES (Advanced Encryption Standard) คืออัลกอริทึมมาตรฐานโลก ทำงานครั้งละ 1 บล็อก (128-bit / 16 bytes)
แต่ความปลอดภัยที่แท้จริงไม่ได้ขึ้นอยู่กับตัวอัลกอริทึม AES เพียงอย่างเดียว แต่ขึ้นอยู่กับ Mode of Operation ที่ใช้ห่อหุ้มบล็อกเหล่านั้น!
🐧 The ECB Penguin Trap: ทำไมห้ามใช้ AES-ECB ในชีวิตจริง?

ECB (Electronic Codebook) เข้ารหัสทีละบล็อก 16 ไบต์แบบแยกอิสระจากกัน: "บล็อก Plaintext ที่เหมือนกัน ย่อมได้บล็อก Ciphertext ที่หน้าตาเหมือนกัน 100%!"

⚔️ การโจมตีขั้นสูงในโหมด CBC (CBC Bit-Flipping & Padding Oracle)
CWE-326 / CTF Classic
ในโหมด AES-CBC ก่อนที่บล็อกถัดไปจะถูกถอดรหัส มันจะถูกนำไป XOR กับ Ciphertext ของบล็อกก่อนหน้า (หรือ IV สำหรับบล็อกแรก):
P2 = Decrypt(C2) ⊕ C1
🎯 เทคนิค CBC Bit-Flipping Attack (เสกสิทธิ์ Admin โดยไม่ต้องรู้ Key!):
สมมติคุ้กกี้เซสชันถูกเข้ารหัสด้วย CBC และมีค่าว่า: user=koon;role=guest
หากแฮกเกอร์เปลี่ยนบิตใน C1 ตรงตำแหน่งของคำว่า 'g' ค่าใน P2 จะเปลี่ยนตามสมการ XOR!
แฮกเกอร์สามารถคำนวณบิตส่วนต่างเพื่อพลิกคำว่า guest ให้กลายเป็น admin ได้สำเร็จ แม้บล็อก C1 จะพัง แต่บล็อก P2 จะกลายเป็นสิทธิ์แอดมินทันที!
#️⃣ 5. Cryptographic Hash Functions & The Salt Defense — การเก็บรหัสผ่านที่ถูกต้อง
ฟังก์ชันแฮชทางวิทยาการรหัสลับ (Cryptographic Hash) ต้องมีคุณสมบัติ: Pre-image Resistance (ถอดกลับไม่ได้), Second Pre-image Resistance, และ Collision Resistance (ไม่มีสองข้อความใดได้ค่าแฮชชนกัน)
รวมถึงการสังเกตปรากฏการณ์ Avalanche Effect (เปลี่ยนแค่ 1 บิต ค่าแฮชเปลี่ยนสิ้นเชิง)

🛡️ ทำไมห้ามใช้ MD5 / SHA-256 เก็บ Password ตรงๆ?
OWASP Authentication
  • MD5 / SHA-1 พังแล้ว: มีช่องโหว่ Hash Collision ที่สร้างไฟล์สองไฟล์ให้ได้ค่าแฮชเท่ากันได้จริง (SHAttered attack)
  • SHA-256 เร็วเกินไป!: การ์ดจอสมัยใหม่ (RTX 4090) สามารถคำนวณ SHA-256 ได้นับหมื่นล้านครั้งต่อวินาที แฮกเกอร์ใช้ Rainbow Tables และ Hashcat ถอดรหัสผ่านได้ในเสี้ยววินาที
  • The Salt Defense: การเติม Salt (สตริงสุ่มอย่างน้อย 16 ไบต์เฉพาะของแต่ละ User) ทำให้ตาราง Rainbow Table ไร้ประโยชน์ทันที
  • วิธีที่ได้มาตรฐานอุตสาหกรรม: ต้องใช้ฟังก์ชันแฮชแบบหน่วงเวลา (Memory-Hard / Slow Hashes) เช่น Argon2id (ชนะเลิศ Password Hashing Competition), bcrypt, หรือ PBKDF2
🗝️ 6. Asymmetric Cryptography — กุญแจคู่ RSA & Diffie-Hellman Key Exchange
วิทยาการรหัสลับแบบอสมมาตร (Public-Key Cryptography) แก้ปัญหาใหญ่ที่สุดในประวัติศาสตร์: "คนสองคนที่ไม่เคยพบกันมาก่อน จะส่งกุญแจลับหากันอย่างปลอดภัยผ่านช่องทางที่ไม่ปลอดภัยได้อย่างไร?"
ด้วยพลังของคณิตศาสตร์ทางเดียว (Trapdoor One-Way Functions) และ Prime Factorization
📐 Interactive Mini-RSA Simulator (คำนวณคณิตศาสตร์สด)

จำลองขั้นตอนสร้างกุญแจ RSA ด้วยจำนวนเฉพาะขนาดเล็ก เพื่อให้เห็นสูตรคณิตศาสตร์: n = p * q, φ(n) = (p-1)*(q-1), d ≡ e⁻¹ (mod φ(n))

🚩 คลังช่องโหว่ RSA ยอดฮิตในสนามแข่งขัน CTF
Crypto CTF Essentials
1. Small N Factorization
หาก n มีค่าน้อยเกินไป (เช่น < 1024-bit) สามารถนำไปค้นหาตัวประกอบแยก p, q ได้ทันทีผ่านเว็บไซต์ factordb.com
2. Wiener's Attack
หากผู้สร้างใช้กุญแจลับ d เล็กเกินไป (d < 1/3 * n^(1/4)) สามารถใช้ Continued Fractions ถอดรหัสได้ในเสี้ยววินาที
3. Small Exponent e = 3
หาก e = 3 และไม่มีการทำ Padding (m^3 < n) สามารถถอดรหัสได้ง่ายๆ เพียงแค่หา รากที่สาม (Cube Root) ของ Ciphertext ตรงๆ
4. Common Modulus Attack
หากใช้ Modulus n เดียวกัน ส่งข้อความเดียวกันด้วยค่า e1, e2 ที่เป็น Co-prime สามารถใช้ Extended Euclidean กู้ข้อความได้โดยไม่ต้องรู้ Private Key
🔏 7. Digital Signatures, PKI & TLS 1.3 — สถาปัตยกรรมกุญแจบนโลกอินเทอร์เน็ต
การเข้ารหัสช่วยรักษา ความลับ (Confidentiality) แต่ ลายมือชื่อดิจิทัล (Digital Signature) ทำหน้าที่รักษา ความถูกต้องแท้จริง (Authenticity) และการปฏิเสธความรับผิดไม่ได้ (Non-Repudiation)
ซึ่งนำไปสู่โครงสร้าง HTTPS / TLS 1.3 ที่รักษาความปลอดภัยให้ทุกลิงก์บนเว็บที่เราใช้งาน

🌐 ส่องการทำงานของ TLS 1.3 (1-RTT Fast Handshake & Forward Secrecy)
RFC 8446
TLS 1.3 ยกเลิกอัลกอริทึมล้าสมัยทั้งหมด (ตัด RSA Key Exchange, ตัด RC4, ตัด CBC) และบังคับใช้เฉพาะ:
  • Ephemeral Diffie-Hellman (ECDHE): สร้างกุญแจชั่วคราวทิ้งทุกเซสชัน เพื่อให้ได้คุณสมบัติ Perfect Forward Secrecy (PFS) — ต่อให้ในอนาคต Server โดนแฮก Private Key หลุด ข้อมูลแพ็กเก็ตที่บันทึกไว้ในอดีตก็ยังถอดรหัสไม่ได้!
  • Authenticated Encryption (AEAD): บังคับใช้เฉพาะโหมดที่ยืนยันความถูกต้องในตัว เช่น AES-GCM, AES-CCM, และ ChaCha20-Poly1305
